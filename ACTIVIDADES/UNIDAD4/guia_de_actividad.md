# Guía de actividades

A continuación, se presentan las orientaciones para las actividades de aprendizaje de la unidad de Gestión de defectos.

## Generalidades

**Tiempo total previsto para el desarrollo de las actividades:** 4 horas.

### Resultados de aprendizaje:

- Resolver problemas de diseño, seguridad y funcionalidad del software, utilizando técnicas avanzadas de depuración, pruebas y evaluación.
- Desarrollar pruebas automatizadas para la integración con pipelines de integración continua.

### Indicadores de desempeño

- Diseña y ejecuta un plan de pruebas integral que contemple cobertura, trazabilidad y automatización, comparando la efectividad de los enfoques Ágil y Cascada para la validación del software.

## Actividades

### Actividad 1: Estructuración e implementación (evaluativa)

Durante esta unidad desarrollarás actividades orientadas a la estructuración e implementación de pruebas de integración y automatización en entornos reales de desarrollo.

#### 1. Ejercicio guiado

Participarás en un ejercicio orientado a:

- Estructurar pruebas de integración.
- Simular entornos de trabajo.
- Comprender la lógica de integración continua (CI) y despliegue continuo (CD).
- Configurar flujos básicos de automatización.

#### 2. Taller práctico (desde repositorio GitHub)

Desarrollarás un taller descargable desde un repositorio en GitHub donde deberás:

- Crear un pipeline de automatización.
- Implementar pruebas de integración (API, UI o integración de servicios).
- Configurar un flujo CI/CD funcional.
- Validar la ejecución automática de pruebas antes de permitir la integración de código.

### Repositorios requeridos

1. **TYVS-Taller_Pruebas_Integracion**
   - 🔗 https://github.com/CesarAVegaF312/TYVS-Taller_Pruebas_Integracion
   - 👉 Utiliza este repositorio como base para desarrollar el taller práctico y estructurar las pruebas de integración.

2. **TYVS-Proyecto_Pruebas_Integracion**
   - 🔗 https://github.com/CesarAVegaF312/TYVS-Proyecto_Pruebas_Integracion
   - 👉 Sobre este repositorio deberás implementar las pruebas automatizadas, configurar el pipeline CI/CD y generar las métricas de cubrimiento solicitadas en el entregable.

#### 3. Cuestionario

Responderás un cuestionario sobre los conceptos abordados en la unidad:

- Integración continua
- Despliegue continuo
- Automatización de pruebas
- Cobertura de código
- Buenas prácticas DevOps

#### 4. Entregable (Evidencia técnica del proyecto integrador)

Cada equipo deberá entregar un repositorio funcional que incluya:

✅ **Requisitos obligatorios**
- Script de pruebas automatizadas
- Pipeline CI/CD funcional
- Métricas de cubrimiento de código
- Reporte de resultados de ejecución
- Restricción de integración: el pipeline debe ejecutar pruebas automáticamente antes de permitir merges o integraciones

## Rúbrica de evaluación

| Criterios de evaluación | Excelente (2 pts.) | Bueno (1.7 pts.) | Necesita mejorar (1.5 pts.) | Deficiente (0.7 pts.) | No cumple (0 pts.) |
|---|---|---|---|---|---|
| **Implementación de pruebas automatizadas** | Implementa pruebas de integración correctamente estructuradas, ejecutables, con buena cobertura y documentación clara. | Implementa pruebas funcionales, aunque con cobertura o documentación parcial. | Presenta pruebas incompletas, con errores de ejecución o baja cobertura. | Las pruebas no funcionan o no corresponden al alcance solicitado. | La actividad no cumple con los criterios establecidos, o no entregó. |
| **Configuración del pipeline CI/CD** | Pipeline completamente funcional, automatiza pruebas correctamente y restringe integración si fallan. (1.5 pts.) | Pipeline funcional, pero con restricciones o validaciones parciales. (1.4 pts.) | Pipeline configurado pero con errores de ejecución o sin automatización completa. (1 pt.) | No existe pipeline funcional o no ejecuta pruebas. (0.8 pts.) | La actividad no cumple con los criterios establecidos, o no entregó. (0 pts.) |
| **Métricas y control de calidad** | Incluye métricas claras de cubrimiento, reporte detallado y análisis de resultados. (1.5 pts.) | Incluye métricas básicas y reporte general. (1.4 pts.) | Presenta métricas incompletas o poco claras. (1 pt.) | No presenta métricas ni reporte de resultados. (0.7 pts.) | La actividad no cumple con los criterios establecidos, o no entregó. (0 pts.) |
